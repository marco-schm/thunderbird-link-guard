## Link Guard 0.12.0

You can now decide which warnings Link Guard shows. Each built-in warning can be
switched off in Settings: lookalike domains, internationalized domain names,
misleading link text, credentials in the URL, IP addresses, unusual ports and
URL shorteners. A warning you switch off also stops requiring an extra
exact-host approval. A link whose analysis failed always keeps its warning.

You can also add your own warnings. A rule has a label and a regular expression
that is checked against the link's host, full URL or visible text. Rules can
come from Settings or from imported warning lists (a JSON file or an HTTPS URL,
format `link-guard-warnings`). Warning lists are shown for review, start
disabled, change only when you refresh them, and can only add warnings, never
approve a link. Patterns run on a small built-in engine whose matching time is
linear, so no rule can freeze Thunderbird; backreferences and lookaround are
not supported. If a message is too large to check within the limit, the
affected links keep a "rules not checked" warning.

Plain `http://` links are no longer flagged as a risk.

Settings now show four separate cards for approved hosts, blocked hosts,
approved whole domains and blocked whole domains. Stored rules are unchanged.

Security fixes: SVG links that use `xlink:href` are now inspected and disabled
until approved, and the approval panel is isolated in a closed shadow root so
that a message's CSS can no longer hide or restyle it.

The permissions remain `messagesRead`, `scripting`, and `storage`. Thunderbird
151 or newer is required. The new interface texts in the 19 non-English
languages have not been reviewed by native speakers. See the [security policy](https://github.com/marco-schm/thunderbird-link-guard/blob/v0.12.0/SECURITY.md)
for limitations. The XPI and `SHA256SUMS` are built only after the YubiKey-signed
tag passes verification.
